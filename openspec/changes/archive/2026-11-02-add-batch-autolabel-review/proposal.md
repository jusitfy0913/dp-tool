# Change: 批量预标注 + 草稿落盘 + 审核快捷键

## Why
现在的预标注只能**一张一张点**，而且草稿只活在内存里：

- 一个 300 张的工程，用户要重复点 300 次「预标注」，期间还要手填引擎路径
  （`annoAlEngine` 是个纯文本框，训练产物就在 `runs/` 下却要人去文件框里翻）；
- 草稿不落盘，**刷新一次全没**——预标注刚跑完，手滑按了 F5 或切了页签，
  几百个框白跑了；
- 审核没有专门的操作手势，只能鼠标点「✓ / ×」，一屏草稿要两次点击 + 移动；
- 草稿全是同一种琥珀色，**看不出哪条值得先看**：0.9 的框和 0.3 的框长得一样，
  人只能逐条读数字。

这四条叠加的结果是："自动标注"名义上存在，实际上没人愿意在真实工程上用。

## What Changes
- **批量预标注**：新增后端后台任务，把整个工程（或「还没有标注/草稿」的子集）
  逐图跑一遍，结果按图片写进草稿池；前端有进度条、当前图片名与停止按钮。
- **闭环打通**：预标注参数区加「训练产物」下拉，直接列 `/api/models` 扫到的
  YOLO 引擎（含体积、是否已转置、配套 `labels`），选中即回填引擎路径与标签文件；
  手工填路径与浏览对话框仍然保留。
- **草稿落盘**：草稿写进工程旁的 `<工程名>.drafts.json`（**不进 `.tfanno`**，
  理由见下）。打开工程自动读回，编辑后防抖增量写回（只写改过的图片）。
- **审核效率**：`A` 接受当前草稿、`D` 丢弃当前草稿、`空格` 下一张；
  并给出「接受当前 / 丢弃当前」两个按钮，让快捷键可被发现。
- **置信度分档着色**：`score >= 0.70` 绿、`0.40 ~ 0.70` 黄、`< 0.40` 红；
  画布边框/标签与草稿列表同色，列表额外给一个「高/中/低」小徽标。

**为什么草稿不塞进 `.tfanno`**：Qt 版保存时会**整体重写**工程文件，未知键不会
被回写。草稿如果住在 `.tfanno` 里，用户用 Qt 打开再保存一次，Web 端刚跑出来的
草稿就静默消失了——这种"看不出来什么时候丢的"故障最难排查。旁挂文件把生命周期
分开：`.tfanno` 仍然只装"人确认过的标注"，与 Qt 的双向兼容不受任何影响。

## Impact
- 影响能力：`web-annotation-workbench`
- 影响代码：
  - `6-web/backend/annotation_drafts.py`（新增：旁挂草稿的读写与规范化）
  - `6-web/backend/autolabeljobs.py`（新增：批量预标注后台任务与进度）
  - `6-web/backend/autolabel.py`（抽出单图执行函数供任务复用）
  - `6-web/backend/app.py`（新增草稿与批量预标注接口）
  - `6-web/frontend/js/api.js`、`js/annotate.js`
  - `6-web/frontend/index.html`、`css/style.css`
  - `6-web/backend/tools/test_annotation_drafts.py`、`test_autolabel_batch.py`（新增）
- 不涉及：`.tfanno` 字段结构、Qt 版代码、导出格式、推理 DLL 契约
- 向后兼容：没有 `*.drafts.json` 的工程行为与现在完全一致（草稿池为空）；
  新增接口全部是追加，不改动既有接口语义
- 已知取舍：批量任务在**服务进程内**跑线程（不是 `/api/runs` 的子进程），
  服务重启后进度丢失，但已写进旁挂文件的草稿不会丢
