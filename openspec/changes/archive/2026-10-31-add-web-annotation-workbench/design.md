# 设计：Web 标注工作台

## Context

### 为什么以 `.tfanno` 为目标格式

Qt 版已有完整的 `.tfanno` 工程实现（`AnnotationProject.cpp` 275 行），且具备两件 Qt 之外的标注器普遍没有的能力：**单文件管理多图**与**数据集划分**。

若 Web 版另立格式，会出现两套互不兼容的数据：Qt 标好的工程 Web 打不开，Web 标好的 Qt 打不开。因此选 `.tfanno` 作为唯一权威格式。

### Qt 读取端的兼容性（已核实）

这决定了扩展字段是否安全：

| 行为 | 出处 | 含义 |
| --- | --- | --- |
| `shapeFromString` 未知类型回落 `Rectangle` | `AnnotationProject.cpp:245-253` | 写错形状名不会崩，但会静默变成矩形 |
| `splitFromString` 未知值回落 `Train` | `:266-271` | 同上 |
| `objectFromJson` 只读已知键 | `:296-310` | **未知键静默忽略 → 扩展字段安全** |
| `score` 缺失时取 `-1.0` | `:306` | 可选字段可省略 |

### 外部标注服务的许可约束（已核实）

`8-X-AnyLabeling-main` 的许可证是 **GPL-3.0**（`LICENSE:1-2`、`pyproject.toml:37`），README 顶部 `LGPL v3` 徽章标注错误。

产品需交付客户，而 GPL-3.0 要求分发时整个衍生作品开源，"UI 开源、其余闭源"不满足该要求。因此只能走进程边界隔离。

## Goals / Non-Goals

**Goals**
- 在浏览器里完成六种形状的完整标注，产出与 Qt 版兼容的 `.tfanno`。
- 补齐 Qt 缺失的编辑手感：顶点编辑、重做、显隐、透明度、分数显示、导航缩略图、十字线、吸附、光标锚点缩放。
- 用自有推理做预标注，零新增依赖。
- 外部标注服务可插拔，且不污染本产品的许可边界。

**Non-Goals**
- 不实现 SAM / 文字提示检测的模型本体，只接外部服务。
- 不改动 Qt 版标注实现。
- 不做多人协作、账号与任务分配。
- 不做视频逐帧标注（Qt 与外部服务都没有这个能力）。
- 不追求外部服务的 13 种导出格式，只做 YOLO / COCO / VOC。

## Decisions

### D1：正方形存 2 点，写入时折叠

Qt 的矩形是 `points[0]` 左上、`points[1]` 右下（2 点对角线，`AnnotationCanvas.cpp:425-426`、`:539`）。外部标注服务的 `rectangle` 是 4 点。

因此：内部统一用 2 点；从外部服务导入 4 点时先规范化再折叠；导出给外部服务时展开成 4 点。这个转换必须集中在数据层一处，不能散落在业务代码里。

### D2：关键点保持 Qt 的"单对象多关键点"模型

Qt 用 `AnnotationObject.shape == Keypoints` + 一个对象装全部点 + `keypointVisibility` 数组（`AnnotationProject.h:48`）。

外部服务是"每个关键点一个 `point` 对象，靠 `group_id` 关联"。两者导出的 YOLO-pose 可能等价，但文件结构完全不同。

选择保持 Qt 模型，理由是：`.tfanno` 是权威格式，若改成外部服务模型，Qt 打开后姿态标注会散成一堆独立点，无法再编辑。导入外部服务的姿态结果时做一次聚合。

### D3：扩展字段用"加键"而非"改结构"

新增 `difficult`（布尔）、`flags`（字典）、`attributes`（字典）三个**顶层新增键**，不改动任何既有键的名称与类型。

原因：Qt 的 `objectFromJson`（`:296-310`）逐键读取，新增键不会影响解析；而改既有键的类型或名称会直接破坏 Qt 兼容。

同时约定：写出的 `.tfanno` 中，这三个键仅在非默认值时出现，减少文件膨胀与无意义 diff。

### D4：撤销与重做用双栈，深度 50

Qt 用单栈快照，深度 50（`AnnotationTab.cpp:882-893`），**没有重做**。外部服务也只有撤销。

改为 `undoStack` + `redoStack`：

- 每次编辑前把当前状态压入 undo，并清空 redo。
- 撤销时把当前状态压入 redo，从 undo 弹出恢复。
- 重做反之。
- 深度 50，对齐 Qt 的既有量级。

替代方案：命令模式（记录操作而非快照）。放弃——快照对当前数据规模（单图几十个对象）足够，且实现简单、不易出错。

### D5：自动保存与重做栈语义分离

自动保存（防抖 3 秒）只负责把数据落到磁盘；重做栈只存活于当前编辑会话。

必须分离的原因：若把"保存"也当作一次编辑压入 undo，用户按撤销会撤销掉保存动作本身，语义荒谬。UI 上需说明"刷新页面后重做历史会清空"。

### D6：乐观锁用自增修订号，不用文件哈希

保存请求携带客户端读到的 `rev`；服务端比对磁盘上的 `rev`，不一致则拒绝并返回冲突。

选自增修订号而非文件哈希的原因：哈希需要每次读全文件计算，且用户可能用外部工具修改文件后哈希变化，产生无法解释的冲突；修订号语义明确。

修订号存放在 `.tfanno` 根级的一个新增键里，Qt 忽略它。

### D7：自动标注分双通道，主通道零依赖

```
               ┌──────────────────────────┐
   预标注请求 →│  autolabel 编排层         │
               └────┬────────────────┬────┘
                    │                │
        主通道（总是可用）      次通道（可选）
                    │                │
          yolo_infer.dll     外部标注服务 HTTP
          自有引擎推理        SAM / 文字提示
```

- 主通道把 `yolo_infer.dll` 的检测框转成矩形标注草稿；若结果带 mask 可转多边形。
- 次通道仅在配置了服务地址时尝试；连接失败给出明确提示并回退主通道，不得静默失败。
- 两条通道的输出统一走同一个"形状转换"函数，保证格式一致。

### D8：预标注结果是草稿层，不是直接写入

理由：预标注必然有误检漏检，直接写入等于把错误固化进工程，用户还得逐个删。

草稿层与已确认标注在画布上用不同样式区分；提供逐个接受、逐个拒绝、全部接受三种操作。草稿不落盘，只在会话内存在。

### D9：图片流走独立接口并受白名单约束

现有 `/static` 只挂载 `frontend`（`app.py:911`），无法直接显示数据集里的图片。新增图片流接口时必须复用 `_ensure_allowed`（`app.py:523-535`），否则等于开了一个任意文件读取口子。

同时需要处理：非 UTF-8 文件名、带空格与中文的路径、超大图的流式输出。

### D10：缩放与平移复用查看器的纯函数

`refactor-web-studio-theme` 已把光标锚点缩放公式抽成纯函数。标注画布必须复用它，而不是再写一遍。

原因：两处实现一旦不同，用户在推理页与标注页会感到"缩放手感变了"，而且这种差异极难在 code review 里发现。

## Risks / Trade-offs

| 风险 | 对策 |
| --- | --- |
| 扩展字段破坏 Qt 兼容 | 已核实 Qt 逐键读取；仍须用真实 Qt 产物做双向往返测试，不靠推断 |
| 姿态标注双向转换丢信息 | 导入时按 `group_id` 聚合，无法聚合的散点保留为独立点并在 UI 提示 |
| 乐观锁被用户绕过（外部改文件） | 检测文件修改时间与体积变化，明显不一致时提示"文件已被外部修改" |
| 大图渲染卡顿 | 画布只渲染可视区域；超大图先降采样预览，导出时用原尺寸 |
| 自动保存覆盖用户的手工修改 | 同一项目同一时刻只允许一个编辑会话；多标签页时用修订号冲突拦截 |
| 外部服务不可用导致功能不可用 | 主通道随时可用；次通道失败必须显式提示而非静默 |
| GPL 污染 | 仅 HTTP 调用，不 import、不打包；分发物中不含其代码；文档写明用户自行安装 |
| 缓存与撤销占用内存 | 快照只存单图标注数组，不存图像位图；深度上限 50 |
| 非 UTF-8 路径导致读图失败 | 路径统一以 UTF-8 处理，文件系统调用显式指定编码 |

## Migration Plan

1. **数据层先行**：`annotation.py` 读写 + 双向兼容测试。这是所有后续工作的地基。
2. **接口层**：project 读写、图片流、导出。
3. **画布基础**：页签、六种形状绘制、缩放平移、撤销重做、快捷键、自动保存。
4. **编辑手感**：顶点/边编辑、显隐、透明度、分数、缩略图、十字线、吸附。
5. **自动标注**：主通道 → 草稿层 → 次通道。
6. 每步可独立验收；前四步完成即已可替代 Qt 标注。

回滚：`.tfanno` 的扩展字段是新增键，若需回滚只需写文件时跳过这三个键；前端为新增文件，删除页签即可。
