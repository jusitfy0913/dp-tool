# 设计：Web 工作站视觉体系与图像查看器

## Context

`6-web` 的前端是**零构建**的：`index.html:409` 只加载一个 ES module `main.js`，没有 npm、没有打包步骤、没有第三方库。这是刻意的设计决策（见 `add-web-studio/design.md`），因为改页面不需要编译是它能快速迭代的根本原因。

因此本次视觉改造有一条硬约束：**不引入任何构建步骤与第三方依赖**。所有效果必须用原生 CSS 与原生 JS 实现。

现状盘点（2026-10-31 实测）：

| 项 | 现状 |
| --- | --- |
| `style.css` 行数 | 244 |
| 颜色变量 | 10 个（`--bg` / `--panel` / `--panel-2` / `--line` / `--text` / `--muted` / `--accent` / `--accent-2` / `--warn` / `--err`） |
| 间距 / 字号 / 阴影 / 动效令牌 | **均无** |
| 响应式断点 | 1 个（`style.css:73`） |
| 图像交互 | **无**，`.images img` 仅 `width:100%`（`style.css:178-186`） |
| `<canvas>` 使用 | 0 处 |
| 图表库 | 无 |

## Goals / Non-Goals

**Goals**
- 建立可扩展的设计令牌体系，让后续页面的样式有一致来源。
- 提供视觉上符合工业检测场景的赛博朋克风格，同时不牺牲长时间阅读日志的舒适度。
- 交付一个**可复用、零依赖、可测试**的图像查看器，供推理页与标注页共同使用。
- 保持零构建：不引入 npm、打包器、CSS 框架、图标字体。

**Non-Goals**
- 不做明暗主题切换（当前只有深色一种使用场景）。
- 不做国际化与多语言。
- 不改动任何后端接口与业务逻辑。
- 不移植 Qt 版的霓虹视觉细节（`4-qt-studio` 的 QSS 主题）。
- 不在本变更内实现标注画布（属 `add-web-annotation-workbench`）。

## Decisions

### D1：设计令牌用 CSS 自定义属性，且分三组

分三组而非一组平铺，是为了让"改主题"与"改尺度"互不干扰：

1. **语义色**（`.theme` 级）：`--bg` / `--surface-1..3` / `--line` / `--text` / `--text-dim` / `--cyan` / `--magenta` / `--amber` / `--danger`。
2. **尺度**（与主题无关）：`--sp-1..6`（4/8/12/16/24/32）、`--fs-xs..xl`、`--radius-sm/md/lg`、`--dur-fast/base/slow`。
3. **效果**（可整体关闭）：`--glow-weak/strong`、`--scanline-opacity`。

第三组单独抽出的原因：可读性护栏与 `prefers-reduced-motion` 需要能一次性把"发光、扫描线、过渡"归零，而不影响前两组。若混在一起，关闭动效时容易连颜色一起改坏。

### D2：赛博朋克风格用"低饱和 + 局部高亮"而非满屏霓虹

工业检测场景的核心需求是**看清缺陷**，不是看界面。

- 背景与面板只做 3 级明度分层（`#0a0e13` / `#111922` / `#182231`），不做大面积渐变。
- 霓虹感只出现在**交互焦点与状态指示**：主色青蓝用于激活态、进度与关键数值；品红仅用于次级强调；琥珀用于警告。
- 扫描线与网格用极低不透明度（默认 ≤ 0.04）叠在页面底层，且**不覆盖图像显示区**——否则会干扰缺陷判读。
- 数据类文本（分数、坐标、耗时）统一 `ui-monospace` 等宽字体并启用 `font-variant-numeric: tabular-nums`，保证数字纵向对齐、便于扫读。

替代方案：满屏发光边框 + 高饱和霓虹。放弃——长时间盯屏易疲劳，且与"看清缺陷"这一首要目标冲突。

### D3：查看器用 CSS transform 而非 canvas 重绘

图像变换用 `transform: translate(x, y) scale(s)` + `transform-origin: 0 0`：

- 只改合成层，浏览器不触发重排与重绘，滚轮缩放手感跟手。
- 不需要按倍率重新采样位图，放大后由浏览器做双线性插值，视觉上足够。
- 标注叠加层可以放在同一变换容器内，随图像一起缩放，无需重复计算坐标。

替代方案：canvas 每帧重绘。放弃——复杂度高、内存占用大，且后续标注页需要矢量叠加层，canvas 重绘方案与它冲突。

### D4：缩放以光标为锚点，公式固定

设变换为 `p_screen = p_image * s + t`，光标屏幕坐标 `c`，缩放前倍率 `s0`、平移 `t0`，新倍率 `s1`：

```
p_image  = (c - t0) / s0
t1       = c - p_image * s1
```

这个公式必须写成纯函数并单测。Qt 版的错误示范是只改倍率不动平移（`AnnotationCanvas.cpp:356-360`），表现为"越缩放，光标下的东西跑得越远"——用户会以为程序坏了。

### D5：窗口开关状态存 localStorage，键名带前缀

键名形如 `trtforge.viewer.<viewId>.enabled`。前缀化的原因：标注页与推理页都有「原图」窗口，若用裸 key 会互相覆盖。

### D6：布局用 auto-fit 网格，不用 flex 换行

```css
.viewer-strip {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(var(--viewer-min, 300px), 1fr));
  gap: var(--sp-3);
}
```

选 `auto-fit` 而非 flex 的原因：flex 在最后一行只剩 1~2 个元素时会把它们拉满，视觉上窗口大小不一致；`auto-fit` 保证同行窗口等宽。3 个窗口在 1920 宽屏下各约 600px，同排显示。

### D7：滚动冲突必须在滚轮处理里显式阻断

查看器内滚轮用于缩放，必须 `event.preventDefault()`，否则会连带滚动整个页面。这是最容易漏且最难在 code review 里看出来的细节，因此写成测试断言。

## Risks / Trade-offs

| 风险 | 对策 |
| --- | --- |
| 视觉改造降低可读性 | 建立对比度下限断言；日志区禁用动效；`prefers-reduced-motion` 全量关闭 |
| 扫描线干扰缺陷判读 | 扫描线只叠在页面底层，图像容器强制 `isolation: isolate` 并置于其上层 |
| 查看器与标注画布各自实现导致手感不一致 | 缩放公式抽成 `viewer.js` 导出的纯函数，标注画布复用它 |
| 窗口多时页面高度塌陷 | 窗口数 > 3 时容器 `overflow-x: auto`，并给窗口固定宽高比 |
| 大图内存 | 查看器只持有一个位图引用，切换图片时显式置空旧图 |
| 触控板惯性滚动被放大成多次缩放 | 滚轮事件做时间窗节流（≥16ms），并对 `deltaMode` 归一化 |

## Migration Plan

1. 先落地令牌与基础组件（不影响现有页面外观是否完全一致）。
2. 逐页替换类名：环境说明页 → 训练页 → 引擎页 → 数据集页 → 推理页。
3. 推理页最后改，因为它要接入查看器。
4. 回滚方式：`style.css` 与 `viewer.js` 均为新增/重写文件，回滚只需还原这两个文件与 `index.html`。
