# design: 原生路径对话框

## 为什么只能由后端弹

浏览器安全沙箱规定：网页无法读取用户选中的本地文件真实路径（`<input type="file">`
只给 `File` 对象和 `fakepath`），更无法调系统文件/文件夹选择框。而后端所有接口要的都是
**服务端机器上的绝对路径**。两条路都不通，只剩一个办法：让后端在它自己那台机器的桌面上
把框弹出来，把路径用 HTTP 回给页面。

前提：服务与浏览器在同一个桌面会话。`scripts/run_web_studio.ps1` 是前台拉起 uvicorn，
满足；用计划任务 / NSSM 跑在无桌面会话时不满足，必须降级（见下）。

## 进程模型

```
浏览器 ──POST /api/browse/dialog──▶ FastAPI（线程池里同步阻塞）
                                      │
                                      ├─ 单例锁（已有框 → 409）
                                      ├─ 写 request.json（临时目录）
                                      ├─ subprocess: pythonw -c <脚本> request.json result.json
                                      │      └─ tkinter：置顶 + 按 kind 选 filedialog
                                      ├─ 等 result.json（超时 300s → kill，按取消处理）
                                      └─ 读 result.json → 规范化路径 → 放行表
```

关键取舍：

| 选择 | 理由 | 不选的反例 |
| --- | --- | --- |
| 独立子进程，不用线程 | tkinter 的事件循环与模态框不适合塞进 uvicorn 线程池 | 同进程内 `Tk()` 在非主线程上行为不稳定，且窗口关闭顺序难控 |
| `pythonw.exe` | 不分配控制台，不会闪黑窗口 | 直接用 `python.exe` 每次点按钮闪一个控制台 |
| 传参走临时 JSON | 中文、空格、引号在命令行里都是坑 | 把路径拼进 `-c` 字符串，遇到 `"` 就崩 |
| 结果走文件，不用 stdout | Windows 控制台编码可能是 cp936，中文路径会乱码 | 读 stdout 需处理 `PYTHONIOENCODING` 与缓冲 |
| 单例锁 | 两个框同时开，用户分不清哪个属于哪个字段 | 允许并发后，取消一个会误以为字段没选上 |
| 超时 kill | 用户可能直接走开，线程不能被永久占住 | 无超时 → 线程池耗尽，整个服务卡死 |

## 本机来源判定

`request.client.host` 属于 `{127.0.0.1, ::1, localhost, ::ffff:127.0.0.1}` 才算本机。
远程用户的框弹在服务端屏幕上，表现为「点了没反应」——比没有这个功能更糟，所以直接 403，
由前端回退页面内浏览。

## 白名单与临时放行

原生框能选到 `D:\数据集`，而 `config.is_path_allowed` 默认只放行仓库根，选完立刻 403。
处理方式：接口在确认「本机 + 用户亲手选中」之后调用 `config.allow_path`，把**该目录**
加入进程级放行表。

三条约束：只加选中那一级（不递归整盘）、不落盘（重启失效）、只在本机来源下触发。
这样既解决体验问题，又不把接口变成「读任意磁盘」的后门。

## 降级路径

| 触发条件 | 表现 |
| --- | --- |
| `/api/capabilities` 的 `native_dialog=false`（非 Windows / 无 tkinter / 显式禁用） | 前端直接走页面内浏览，不发请求 |
| 403（远程来源） | 提示原因 + 自动打开页面内浏览 |
| 409（已有框） | 只提示「先处理已打开的选择框」，不叠框 |
| 400（环境不支持、参数非法） | 提示原因 + 自动打开页面内浏览 |
| 用户取消 | 不改字段、不提示、不打开页面内浏览 |

## 交互约定

| 操作 | 行为 |
| --- | --- |
| 单击 | 原生框（按字段类型：文件 / 多选 / 文件夹 / 另存为） |
| `Shift` + 单击 | 页面内目录浏览 |
| 「文件」+「目录」双按钮字段 | 分别弹文件框和文件夹框（Windows 框无法一次同时选两者） |
| 「选图片…」 | 多选文件，逐张向后端问尺寸后插入工程 |

## 测试策略

模态框无法自动点击，所以把「弹框」这一步替换成假子进程（写一份 result JSON 就返回），
验证我们自己写的逻辑：扩展名归一化、起始目录取父目录、四种类型映射、单例锁、超时、
子进程异常、无结果文件、取消不写记忆、临时目录清理、白名单放行/清空、
接口层远程 403 与本机放行。

真实弹窗由一次人工/自动化确认：点按钮 → 桌面截图确认框出现 → 输入路径回车 → 校验字段值。
