## ADDED Requirements

### Requirement: ONNX 推理动态库与 C ABI

系统 SHALL 提供独立的 `onnx_infer` 动态库，导出稳定的 C ABI（`oi_*`），供 Python ctypes 与外部 C++ 程序加载使用，不得要求调用方链接 C++ 运行时或了解内部实现。

#### Scenario: Python 通过 ctypes 调用

- **WHEN** Python 程序以 `ctypes.WinDLL` 加载 `onnx_infer.dll` 并声明 `oi_*` 函数原型
- **THEN** 该程序必须能够创建句柄、执行一次推理、深拷贝返回的结构体与指针内容、销毁句柄，且不得需要额外安装 Python 侧的推理依赖

#### Scenario: 外部 C++ 调用

- **WHEN** 外部 C++ 程序加载或链接 `onnx_infer`
- **THEN** 该程序必须能够完成同样的创建、推理、读取结果与销毁流程，且头文件只依赖 C 语法与固定宽度整数

#### Scenario: 结果内存生命周期

- **WHEN** 一次推理成功返回
- **THEN** 结果结构体及其中的图像与掩码指针必须只在下一次推理或销毁句柄之前有效，且头文件中必须写明调用方需要立即深拷贝

#### Scenario: 非 ASCII 路径

- **WHEN** ONNX 模型或 `metadata.json` 的路径包含中文或其他非 ASCII 字符
- **THEN** 动态库必须能正常加载，路径参数一律按 UTF-8 解释，内部转换为宽字符后再访问文件

#### Scenario: 一个句柄不跨线程并发

- **WHEN** 调用方需要对同一模型并发推理
- **THEN** 调用方必须创建多个句柄，动态库不得声称单个句柄可被多线程同时调用

### Requirement: ONNX 模型任务覆盖

动态库 SHALL 支持 YOLO 的 `detect`、`segment`、`pose`、`obb` 四项任务，以及 Anomalib 的 PatchCore、PaDiM、EfficientAd 三类异常检测模型，且必须直接从模型输入输出形状推导类别数、关键点数与输出布局，不得按任务写死通道数。

#### Scenario: 四类 YOLO 任务

- **WHEN** 调用方以 `.onnx` 路径和对应任务类型创建句柄并推理
- **THEN** 返回的框、掩码、关键点或旋转框字段必须与同任务 TensorRT 路径的结构同构，且字段名与顺序一致

#### Scenario: 两种输出布局

- **WHEN** 模型的检测输出为 `[1, 4+类别数, 候选框数]` 或 `[1, 候选框数, 4+类别数]`
- **THEN** 动态库必须两种都能正确解析，并在均不匹配时于错误信息中报出实际形状

#### Scenario: 关键点数不写死

- **WHEN** 姿态模型的通道数为 `5 + 3k`
- **THEN** 动态库必须以 `k` 作为关键点数量解码，且当通道数无法按该形式整除时返回可读错误而不是越界读取

#### Scenario: 任务与模型不匹配

- **WHEN** 调用方为分割模型选择 `detect` 任务，或为检测模型选择 `segment` 任务
- **THEN** 创建句柄必须失败，且错误信息必须指出当前模型更像哪类任务、应该切换到哪一项

#### Scenario: 三类异常检测模型

- **WHEN** 调用方以 PatchCore、PaDiM 或 EfficientAd 导出的 `.onnx` 与配套 `metadata.json` 创建句柄
- **THEN** 动态库必须返回原始分数、归一化分数、判定结果与归一化异常图，且分数为一维或二维张量时都能解析

### Requirement: 执行后端选择与回退

动态库 SHALL 默认保证 CPU 可用，并在运行时确认 CUDA 执行提供程序可加载后才使用它；CUDA 不可用或会话创建失败时必须自动回退到 CPU，且实际使用的提供程序必须可被调用方查询。

#### Scenario: CUDA 可用时使用 CUDA

- **WHEN** 运行环境存在可加载的 CUDA 执行提供程序且会话创建成功
- **THEN** 推理必须使用 CUDA，并通过信息查询接口报告实际的提供程序名称

#### Scenario: 缺少 CUDA 时回退

- **WHEN** CUDA 执行提供程序的动态库缺失或无法加载
- **THEN** 动态库必须只使用 CPU 创建会话，推理正常完成，不得把加载失败当作致命错误抛给调用方

#### Scenario: 会话创建失败时回退

- **WHEN** 带 CUDA 的会话创建抛出异常（如 cuDNN 版本不符或显存不足）
- **THEN** 动态库必须改用 CPU 重建会话并继续推理，且查询接口报告的提供程序必须与实际情况一致

#### Scenario: 线程数可配置

- **WHEN** 调用方设置了线程数环境变量
- **THEN** CPU 会话的算子内并行线程数必须使用该值；未设置时使用库的默认值

### Requirement: 与 TensorRT 路径的行为等价

ONNX 动态库 SHALL 与既有两个 TensorRT 动态库使用同一套阈值语义、判定口径与结果渲染规则，使同一模型在不同后端下给出可比较的结论。

#### Scenario: 异常检测阈值语义

- **WHEN** 调用方传入不小于 0 的图像阈值或像素阈值
- **THEN** 该值必须覆盖 `metadata.json` 中的对应值；传入负数时必须沿用文件中的值

#### Scenario: 判定口径

- **WHEN** 归一化分数落在阈值边界上
- **THEN** 判定规则必须与 TensorRT 路径一致（归一化分数不小于 0.5 判为异常）

#### Scenario: 渲染输出同构

- **WHEN** 一次异常检测推理完成
- **THEN** 必须同时返回原图、叠加图、红色异常轮廓图与归一化异常图，尺寸与原图一致，且配色与叠加权重与 TensorRT 路径相同

#### Scenario: 阈值逻辑只有一份

- **WHEN** 两个动态库都需要把原始分数与异常图归一化
- **THEN** 它们必须共用同一份实现，不得各自维护一份等价的副本

### Requirement: ONNX 与 TensorRT 输出一致性校验

系统 SHALL 提供可反复执行的一致性校验工具，在相同输入与相同参数下比对 `.onnx` 与 `.engine` 两条后端的输出，并对不达标情况给出非零退出码。

#### Scenario: 结果级比对

- **WHEN** 调用方给出同一个模型的引擎、ONNX、任务类型与图片目录
- **THEN** 工具必须逐图分别通过两条后端推理，并输出框数量、匹配率、最小交并比、置信度差、掩码交并比、关键点距离、旋转框角度差、分数差、判定一致性与异常图差值

#### Scenario: 判定阈值

- **WHEN** 任一指标超出默认阈值
- **THEN** 工具必须以非零退出码结束并指出具体图片与指标，不得只打印警告后返回成功

#### Scenario: 阈值可覆盖

- **WHEN** 调用方显式传入阈值参数
- **THEN** 工具必须使用传入值判定，并在报告中记录本次使用的阈值

#### Scenario: 无法比对时明确失败

- **WHEN** 引擎或 ONNX 其一不存在、DLL 不可用，或图片目录为空
- **THEN** 工具必须返回区别于「比对不通过」的退出码并说明原因，不得当作通过

#### Scenario: 报告可追溯

- **WHEN** 一次比对结束
- **THEN** 必须产出包含逐图明细的 JSON 与 CSV，CSV 使用 `utf-8-sig` 编码以便 Excel 直接打开不产生乱码

### Requirement: 原始张量诊断导出

动态库 SHALL 支持在诊断开关开启时导出预处理后的输入张量与后处理前的输出张量，用于把差异定位到预处理、模型数值或后处理层；开关关闭时行为与性能必须与未实现该功能时一致。

#### Scenario: 开关关闭时零影响

- **WHEN** 未设置诊断目录环境变量
- **THEN** 动态库不得创建任何文件、不得改变返回结果与耗时统计

#### Scenario: 开关开启时落盘

- **WHEN** 设置了诊断目录环境变量
- **THEN** 每次推理必须把输入张量与每个输出张量按后端与序号落盘为 float32 原始数据，并写出包含形状、数据类型与提供程序的清单文件

#### Scenario: 张量对齐

- **WHEN** 两侧输出张量的维度顺序不同（如 `[1, 通道, 点数]` 与 `[1, 点数, 通道]`）
- **THEN** 比对工具必须自动对齐后计算最大绝对差、平均绝对差与余弦相似度，并对无法对齐的形状差异明确报错
