## Context

`val_engine.py` 已经用 `--min-score 0.001` 把引擎的所有框跑出来了
（`6-web/backend/tools/val_engine.py:255`），但 `evaluate()` 只按一个 conf 汇总成 P/R。
也就是说「曲线所需的数据早就在内存里」，缺的只是把它按阈值切片。

第二个缺口是「良品图」。当前扫描把「没有标签文件」和「标签为空」混成一类，都只发一句
warning（`6-web/backend/dataset.py:526`）。如果把漏标当良品，过杀率会被算成 0——
这是最危险的一种「报告好看」。

## Goals / Non-Goals

- Goals
  - 一条命令/一个接口就能拿到「漏检率 ↔ 过杀率」曲线与反查工作点。
  - 良品图必须由人显式声明，工具不猜。
  - 选定工作点可保存、可追溯，推理页默认使用它。
  - 自动实验的 KEEP 不能「拿过杀换 mAP」而没人发现。
- Non-Goals
  - 不改 `yolo_infer.dll`、不改 `metadata.json`（工作点只写引擎旁挂文件）。
  - 不做分割/姿态/OBB 的工作点（GT 匹配口径不同，`val_engine.py:167` 已明确拒绝）。
  - 不做自动调参把 conf 调到目标漏检率（只给建议点，由人决定是否保存）。

## Decisions

### 1. 良品图 = 标签文件存在且为空

`val_engine.py` 逐图判定三种状态：

| 状态 | 判据 | 计入 |
| --- | --- | --- |
| `labeled` | 标签文件存在且解析出 ≥1 个框 | 漏检统计 |
| `ok` | 标签文件存在、内容为空 | 过杀率 / 良品误报率 |
| `missing` | 标签文件不存在 | 单独计数，不算良品，报告警告 |
| `unparsed` | 文件非空但一行都解析不出来 | 单独计数，报告警告 |

理由：数据集导出永远会写 `.txt`（`dataset.py:1016`），所以「导出后的数据」天然满足这条判据；
而原始数据里「漏标」不会凭空长出空文件。这条判据让「良品」与「漏标」在磁盘上可区分，
不需要额外的清单文件。

### 2. 曲线用一次匹配 + 前缀累加，不重复扫

贪心匹配按分数降序处理，删掉低分框不会改变高分框的匹配结果（COCO 也是这个性质）。
所以每类只算一次 `_match_flags`（在 `min(confs)` 下），再按 conf 取前缀求
`cumsum`，得到全部阈值点的 TP/FP。复杂度 O(P×G)，与点数无关。

### 3. 过杀率给两个数

- `fp_per_image` = 全部 FP 框 / 评估图片数（含 NG 图上的多检）——对应产线「每张图报几次」。
- `ok_fp_rate` = 有 ≥1 个 FP 的良品图数 / 良品图数——对应「好品被误杀」。

两者不可互相替代：把 NG 图上的漏框补成两个框，`fp_per_image` 会涨但良品图仍然干净。

### 4. 工作点只写 `<engine>.meta.json`

新增 `operating_point: {conf, iou, source, recall, miss_rate, fp_per_image, ok_fp_rate, saved_at}`。
理由：`metadata.json` 是 DLL 的输入契约，写进去会改变已有引擎的行为；而引擎旁挂文件
本来就是 2.1 建立的「引擎来源说明」，语义一致。

推理页读取规则：引擎旁挂文件里有 `operating_point.conf` 时，预填 conf 并在提示条说明
「来自引擎工作点（保存于 …）」，用户改过之后以用户输入为准。

### 5. autoexp 的过杀率是近似值，且必须标注

Ultralytics 的 `results.csv` 没有 FP 计数。用 `P`、`R` 与 val 集的 GT 数反推：

    TP = R × N_gt ,  FP = TP × (1 - P) / P ,  fp_per_image = FP / N_images

这个值对应的是**best-F1 conf**（Ultralytics 的 P/R 就在该点取值），不是固定 conf，
也不区分良品图。因此：
- 台账列名用 `fp_per_image`，文档写明它是近似值；
- KEEP 约束只在候选与基线**都有该值**时生效；
- 容差取 `max(0.01, 基线 × 5%)`——低于这个量级的差异不能当作「过杀变差」。

## Risks / Trade-offs

| 风险 | 缓解 |
| --- | --- |
| 用户把漏标目录误勾成良品 | 该目录里任何一张图有标注就整个目录报错并拒绝；导出前在扫描预览里单列良品张数 |
| 良品图全进 val，训练集里没有负样本 | 刻意取舍：本轮目标是「验收」，训练用负样本留到后续；文档写明 |
| 曲线点太密影响响应 | 固定 19 点（0.05~0.95，步长 0.05），可传自定义但上限 50 |
| autoexp 近似过杀率误导 | 列名与文档标注「近似」，且不做硬门槛以外的展示（不写进 best.json 结论） |

## Migration Plan

- `ok_dirs` 默认空、`ok_split` 默认 `val`：不传时扫描/导出结果与已有一致。
- `results.tsv` / `holdout.tsv` 按列名迁移，旧行该列留空（沿用 `ensure_tsv`）。
- 旧引擎没有 `operating_point`：推理页保持原默认值，不报错。

## Open Questions
