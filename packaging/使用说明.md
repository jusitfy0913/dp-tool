# 发给使用人员

这是可以双击使用的缺陷检测软件。安装目录里没有开发用的源码。

软件本体和示例模型是**两个包**，分开下载、分开更新：

| 包 | 里面有什么 | 大约多大 |
| --- | --- | --- |
| `TRTForgeWeb`（本目录） | 软件本体：网页程序、推理运行库、训练环境安装脚本、操作手册 | 1.8 GB |
| `TRTForgeWeb_models_demo` | 示例模型：PCB 缺陷检测、EfficientAd 异常检测（**只有 ONNX**） | 40 MB |

只要软件、不需要现成模型时，只装第一个包就行。想马上试推理，再装第二个。

## 对方电脑需要

- 64 位 Windows 10 或更高
- NVIDIA 显卡驱动（支持 CUDA 11.8 的驱动即可，不必再单独装 CUDA 工具包）
- 微软 Visual C++ 2015–2022 x64 运行库。缺了会提示找不到 VCRUNTIME。到微软官网搜索这个名字安装。

## 第一次使用

1. 把整个 `TRTForgeWeb` 文件夹拷到对方电脑，例如 `D:\TRTForgeWeb`。不要只拷其中一个文件。
2. 双击 `install_train_env.bat`。这一步要联网，会在旁边生成 `train-env`，并自动把 Python 路径写进 `config.json`。对方电脑不必事先安装 Anaconda 或 Miniconda，脚本会自己下载环境工具。只想检测、暂时不训练的人可以先跳过，但训练按钮会不可用。虚拟机或没有 AVX2 的处理器上，脚本会改用 Polars 兼容包，避免一点「检测环境」就崩溃。
3. 用记事本打开 `config.json`：
   - `port`：网页端口，默认 8060
   - `host`：只本机用就留 `127.0.0.1`。车间其他电脑也要打开时，改成 `0.0.0.0`
   - `data_roots`：图片和数据集所在的文件夹，例如 `["D:\\检测数据"]`。可以写多个
4. 双击 `app\TRTForgeWeb.exe`。浏览器会自己打开软件。右上角变成「环境就绪」就可以按《操作手册》使用。

   也可以双击安装目录里的 `start_web.bat`，效果完全一样（它只是转手调同一个 exe）。
   已经开着的时候再双击一次，不会开第二个，只会把浏览器重新打开。

启动出问题会弹一个中文框，写明「发生了什么、为什么、该怎么办」；
完整过程记录在 `runtime\logs\launcher.log`，需要求助时把这个文件发出去即可。
详细的排障步骤见 `docs\启动与排障说明.md`。

操作手册在 `docs\TRTForge_Web操作手册.md`。用支持 Mermaid 的 Markdown 预览打开，才能看到流程图。

## 装示例模型（可选）

1. 把 `TRTForgeWeb_models_demo` 解压到软件目录**旁边**，与 `TRTForgeWeb` 同级：

   ```
   D:\TRTForgeWeb\                 ← 软件
   D:\TRTForgeWeb_models_demo\     ← 示例模型
   ```

2. 双击示例模型包里的 `install_demo_models.bat`。脚本自己找到软件目录，按软件能认的结构拷进去，并逐个校验 SHA256。
3. 打开软件的「引擎构建」页，选示例模型里的 `.onnx`，**输出引擎留空**，精度选 FP16，点开始构建。
   引擎必须在**这台电脑的显卡**上编一次：`.engine` 绑定显卡型号与 TensorRT 版本，开发机编好的换台机器会报错。
4. 编完之后回到「推理演示」页，模型下拉里就能选到示例模型。

装的是哪几个模型、每个多大、编一次大概多久，见示例模型包里的 `README_示例模型.md`。
软件目录下 `models\README.txt` 也有一份简版说明。

不装示例模型也能正常使用：训练、标注、引擎构建、文字识别都不依赖它，只是推理页一开始没有可选模型。

## 包里不含你的 API Key

自动实验（大模型帮你挑训练参数）的 Key 存在开发机上，**不会**进这两个安装包。
打包脚本在压缩前会扫描整个目录，发现 Key 就停止打包，压缩包根本不会生成。

对方要用这个功能，需要自己在网页「自动实验」页填一次自己的 Key。Key 只保存在
他本机，不会回传到开发机；而且从 v1.35.3 起是**加密保存**的（Windows DPAPI）——
只有那台电脑的那个 Windows 账户能解开，别人把这台机器的文件夹拷走也读不出明文。
换电脑、重装系统或换 Windows 账户后，网页会提示「请重新输入」，这是正常现象，
重新填一次即可。

万一你怀疑 Key 已经随某个包发出去了，请立刻去厂商后台**吊销并重新生成**——
删掉文件是没用的，拿到包的人早就存下来了。

## 结果会写到哪里

训练页的「输出目录」如果留着默认的相对路径，文件会落在本安装目录的 `launchers\runs`（YOLO）或 `launchers\results`（异常检测）。想放到数据盘，就在页面里改成绝对路径，例如 `D:\检测数据\训练结果`。

## 目录结构（对方看不看都行）

| 目录 | 作用 |
| --- | --- |
| `app\` | 编译后的网页程序 |
| `bin\` | CUDA / TensorRT / OpenCV 运行库与推理 DLL |
| `frontend\` | 网页界面文件 |
| `launchers\` | 训练启动器；`runs\` 放 YOLO 产物，`results\` 放异常检测产物 |
| `models\` | 文字识别与提示式标注的模型；示例模型不装在这里，装在上面两行说的 `launchers` 下 |
| `runtime\logs\` | 运行日志。启动失败先看 `launcher.log`，训练与推理日志在同目录 |
| `docs\` | 操作手册 |

## 第三方许可

训练环境会从互联网安装 Ultralytics 与 Anomalib。Ultralytics 使用 AGPL-3.0。本安装包不附带它们的源码。对外发放前，请自行确认是否符合这些库的许可，或是否已取得商业授权。
